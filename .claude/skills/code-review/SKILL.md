# 代码审查技能

## 触发场景
- 功能开发完成
- PR 提交前
- 代码合并前

## 执行流程

### 阶段1: 读取代码
读取待审查的文件和相关上下文。

### 阶段2: 多维度审查
使用 code-reviewer 代理进行审查：
1. **正确性**: 逻辑是否正确
2. **安全性**: 是否有安全漏洞
3. **性能**: 是否有性能问题
4. **可维护性**: 是否清晰易懂
5. **测试**: 测试是否充分

### 阶段3: 输出审查报告
- 总体评价
- 问题列表（按严重程度）
- 改进建议

### 阶段4: 修复确认
如果发现问题，修复后需要再次审查。

## 约束
- 必须使用 code-reviewer 代理
- 审查结果必须记录到 `docs/knowledge/pitfalls.md`
- 审查不通过不能提交代码
