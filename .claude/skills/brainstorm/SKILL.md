# 头脑风暴技能

## 触发场景
- 用户提出模糊需求，需要澄清
- 有多种技术方案需要评估
- 需要用户确认设计方向

## 执行流程

### 阶段1: 需求澄清
使用苏格拉底式提问帮助用户理清需求：
1. **业务目标**: 这个功能要解决什么问题？
2. **用户场景**: 谁会在什么场景下使用？
3. **约束条件**: 有哪些技术、时间、资源限制？
4. **成功标准**: 如何判断这个功能是否成功？
5. **边界情况**: 有哪些特殊情况需要考虑？

### 阶段2: 方案探索
提出 2-3 种可行的技术方案：
- 方案 A: [描述] — 优点 / 缺点
- 方案 B: [描述] — 优点 / 缺点
- 方案 C: [描述] — 优点 / 缺点

### 阶段3: 方案推荐
基于项目约束给出推荐方案，等待用户确认。

### 阶段4: 输出制品
- `Task List` — 确认的任务清单
- `Design Document` — 设计方案文档

## 使用示例
```
/brainstorm 实现用户 API Key 管理功能
```

## 输出格式
```markdown
# 头脑风暴结果

## 需求澄清
- **业务目标**: ...
- **用户场景**: ...
- **约束条件**: ...

## 可选方案
### 方案 A: ...
- 优点: ...
- 缺点: ...

### 方案 B: ...
- 优点: ...
- 缺点: ...

## 推荐方案
[推荐方案及理由]

## 下一步
请确认方案，我将生成规范文档。
```
